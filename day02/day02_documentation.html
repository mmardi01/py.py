Chapter I & II

What the subject asks for

Constraints from the PDF that shape how every file below is written — they explain the blank lines, the main() wrapper and the bare except as much as the pandas does.

No code in global scope

Every program is a def main(): plus the if __name__ == "__main__": guard. Nothing executes on import.

No uncaught exception

An exception escaping to the terminal invalidates the exercise — including for errors the subject explicitly asks you to trigger.

Explicit imports only

from pandas import * scores 0. Hence import pandas as pd and from load_csv import load.

flake8 is the norm

pip install flake8, aliased to norminette. Two blank lines between top-level definitions, ≤79 columns per line — which is why several calls below are split across two lines.

Python ≥ 3.10, no globals

State travels through parameters and return values only.

Every graph is labelled

ex01 onwards: a title and an axis legend on both axes; ex02 and ex03 add a legend per plotted series.

The CSV files

One row per country, one column per year

Gapminder ships its tables in wide format. The first column holds the country name; every remaining column header is a year, stored as text. That single fact drives almost every slice in the code: column 0 is always the label, columns 1: are always the timeline.

Exercise 00 · load my dataset

load_csv.py

A function that takes a path, prints the dimensions of the dataset and returns it — returning None when the path is bad, the format is wrong, or anything else goes sideways. This exact file is copied into ex01, ex02 and ex03 unchanged.

Two blank lines before a top-level def — flake8 rule E302.
4

Signature. path: str is a type annotation — pure documentation, Python does not enforce it at runtime. The subject's version also annotates a return type; here the return type is left open because it is either a DataFrame or None.

Everything that can raise goes inside. Without this block a missing file would print a traceback and invalidate the exercise.

The actual work. Opens the file, treats the first line as the header, infers a dtype per column, and returns a DataFrame — a 2-D table with labelled columns and a positional row index. The required output. .shape is an attribute, not a call — a tuple (rows, columns). print joins its two arguments with a single space, so the tuple prints as (195, 302).

Deep dive · ex02 line 36

What plt.legend(loc='lower right') actually does

Two separate questions live in this one call: what goes in the box — which is decided eight lines earlier, not here — and where the box goes, which is what loc controls.

label= alone draws nothing

Setting label= without ever calling legend() produces no box. The string just sits on the artist, unused.

legend() alone draws nothing either

With no labelled artists, matplotlib emits “No artists with labels found to put in legend.” and no box appears. A line plotted without label= is auto-named '_child1', and names starting with an underscore are deliberately skipped.

Both are needed, in this order

label= on every series first, one legend() at the end. That pair is what satisfies the subject's “a legend for each graph”.

Then: where the box lands

'best'0Default. matplotlib measures the drawn data against all nine boxes and picks the one it overlaps least — it is the only value that costs computation.
'upper right'1Corner anchors — the box is pushed into that corner of the axes.
'upper left'2
'lower left'3
'lower right'4Used in ex02.
'right'5Kept for backwards compatibility; equivalent to 'center right'.
'center left'6Edge midpoints.
'center right'7

Beyond the nine boxes

loc also accepts a coordinate pair in axes fractions — loc=(0.35, 0.7) places the box's lower-left corner at 35% across and 70% up. Pairing loc with bbox_to_anchor= moves the key outside the plot area entirely, and ncol=, frameon=False and title= change how the box itself is drawn.

Deep dive · ex03 line 17

What plt.xscale('log') actually changes

One idea, and everything else follows from it: a normal axis puts a value at a distance proportional to the value. A log axis puts it at a distance proportional to log₁₀ of the value. The numbers you plotted never change — only where matplotlib decides to paint them.

Valuelog₁₀(value)Position on a linear axisPosition on a log axis
1011 unit from the origin1 step
100210× further out than 102 steps — one step past 10
1 0003100× further out than 103 steps — one step past 100
10 00041000× further out than 104 steps — one step past 1 000

Each ×10 in the data becomes a fixed, equal distance on screen — a “decade”. That is the whole trick: equal ratios take equal space, where a linear axis gives equal space to equal differences.

What it does not touch

The data. incomin_data still holds 1050, not 3.02. xscale only replaces the function that maps a value to a pixel — a display setting on the axes, applied at draw time.

x only

xscale changes the horizontal axis alone; the y axis stays linear unless you also call plt.yscale('log'). In ex03 life expectancy runs 20 → 55, a narrow range where a linear axis already reads fine.

Why the ticks needed fixing

A log axis labels its decades by default — 10², 10³, 10⁴. That is exactly why line 18 follows with plt.xticks([300, 1000, 10000], ['300', '1k', '10k']) to write plain numbers instead.

Zero has no place on it

No power of 10 equals 0, and negatives have no logarithm — so a log axis cannot position them and matplotlib drops those points. Incomes start at 360, so nothing is lost here.

When a log axis is the right call

Reach for it when your values span orders of magnitude — incomes, populations, file sizes, city sizes — or when the interesting thing is growth rates rather than absolute amounts. On a log axis, steady exponential growth draws as a straight line, and two countries growing at the same rate draw as parallel lines regardless of how far apart their totals are. Richter, decibels and pH are the same idea baked into a unit.
